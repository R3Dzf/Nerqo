# Nerqo 1.0.8 Stable

## Preparation and transfer feedback

Windows creates a stable shared-file snapshot while computing SHA-256 in the
same read/copy pass. It no longer rereads the entire snapshot to hash it.
Preparation reports percentage progress and removes incomplete snapshots after
cancellation. Sharing still finishes preparation before advertising the file;
this is not immediate streaming from an unlocked source. A changed original
cannot silently change the prepared download.

The Windows incoming queue shows saved uploads and committed bytes, including
paused uploads. Lists of shares and paired devices are rebuilt only when their
contents change, rather than on every upload checkpoint.

## Persistent History

Windows and Android now have separate History pages with search and status
filters. The available-shares list is labelled accordingly and remains in
Transfers. History begins with new operations; old available shares are not
invented as completed deliveries.

Android retains the latest status of each file/folder job (including paused,
interrupted and cancelled jobs) across restarts, up to 500 records. Resuming a
job updates its existing row. Cancellation can clear the local job even if
best-effort server cleanup is unavailable; completed files remain intact.

Windows records completed received files, cancelled uploads and integrity
failures. Folder members appear individually. Outgoing file/folder deliveries
are recorded only after a receiving 1.0.8 Android client confirms its verified
receipt. These acknowledgements are best effort; loss of an acknowledgement
can leave a completed outgoing delivery absent from Windows History. Reading
or advertising a share alone never marks it as delivered. Old clients continue
to transfer files but do not send these new receipt acknowledgements.

Windows History is stored separately from frequent transfer checkpoints, and
logging write failures do not fail a verified transfer. A History warning
identifies records kept only in memory if the log cannot be saved/read.

History stays local; metadata is bounded to 500 entries per device. It contains
file/job titles, device names, states and timestamps, and can include local
error details. Receipt replay does not duplicate Windows records.

The Windows update dialog explicitly distinguishes full downloads from deltas
without repeating the full size when no compatible delta is available.

## Validation and limits

Host acceptance covers preparation checksum/progress, snapshot stability after
source edits, cancellation cleanup, receipt validation/idempotence and saved
history reload. Android instrumentation covers status upserts and history
reload, plus existing TLS/SAF interruption tests. UI checks capture History on
both platforms. Stable signing, version matching, replacement installation,
installer delta budget and reconstruction gates remain required.

This release does not add background transfer services, automatic 5 GHz control,
new radio transports or a reconnect-without-repairing protocol. Real-device
throughput, battery and physical camera/hotspot acceptance remain outstanding.
