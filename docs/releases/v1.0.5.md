# Nerqo 1.0.5 Stable

## Windows connection fixes

- Corrects false Firewall block detection: rules restricted to another Windows
  service no longer count as blocks on the Nerqo desktop process. General rules
  restricted to other addresses, ports or interface types no longer prove the app
  is blocked. A relevant detected block now includes the rule name for review.
  No Windows Firewall rules are removed or weakened by this detection change.
- One native instance per Windows user/session. Opening Nerqo again restores the
  existing window instead of starting another listener on the same port.
- A receiver startup failure shows its actual exception and offers Retry receiver
  and Copy connection details. A later network/QR/tray error no longer incorrectly
  reports that an already running receiver is not listening.
- Failed listener starts are disposed before retry. After the user chooses to
  launch an update installer, Nerqo exits its own receiver to release its files.

Before the first launch after upgrading from 1.0.4 or earlier, exit all older
Nerqo instances from their tray menus. Older processes do not know the new
single-instance coordination. Keep existing Firewall rules unchanged unless an
identified rule actually requires review. If the receiver still cannot start,
use Copy connection details to report the actual error; this release does not
claim to diagnose an unseen physical-device error from a cropped screenshot.

## Delivery

Windows and Android retain coordinated version 1.0.5 and the permanent Android
signing identity. Compatible deltas from 1.0.4 and full-download fallback are
published with SHA-256 metadata. The Firewall scope and remaining platform
limits in the 1.0.4 notes still apply. Actual Windows-user UAC interaction and
physical-device network acceptance remain outside automated CI validation.
