# Nerqo v1.0.10 Stable

## Instant local updates and persistent device connection
- Windows and Android use an authenticated, certificate-pinned TLS connection on the local network. Windows sends change notifications immediately over a bounded server-sent-events (SSE) channel; Android then fetches the current verified items once. This replaces Android's previous periodic seven-second item refresh.
- Initial subscription and every reconnect immediately synchronize the complete list, preventing missed changes after a Wi-Fi or hotspot interruption. Heartbeats are transport-level keepalives, not repeated item downloads.
- A visible Android `connectedDevice` foreground service keeps the subscription open when the Activity is closed, with Disconnect in the notification. Foreground service lifetime follows Android OS power management; force-stop, permission revocation, certain vendor battery savers and unavailable Wi-Fi may interrupt it.
- Android retries with bounded backoff and promptly reacts to Wi-Fi state changes. Discovery after an IP change is authenticated against the previously pinned Windows TLS certificate before credentials are reused. Forget/Disconnect stop the live service.
- Windows WPF rendering now follows server state/progress changes instead of refreshing every 500 milliseconds. Changes are coalesced on the UI dispatcher.
- Windows History status dropdown uses the active app palette in dark and light themes, including the popup and selected/highlighted options.

## Security and privacy
- No cloud account, Internet access, WebView, or browser connection is required to transfer data on the local network.
- Event notifications never include filenames, copied text, tokens or file bytes. Requests are authenticated and suspended/revoked peers cannot continue receiving updates indefinitely.
- No background reads of other Android apps' clipboard are attempted; clipboard synchronization remains outside this stable feature set.
- Existing per-user Windows installer identity and Android package/signing certificate must remain unchanged. Android release cannot ship without a verified APK signed by the original certificate.

## Validation and limitations
Windows host integration, SSE security and instant delivery checks, WPF UI smoke, Android HTTPS/SAF instrumentation, Compose emulator tests, and a real installer upgrade from 1.0.9 are gates to publication.

No user hardware is available to validate specific TECNO battery-management behavior, sustained throughput, radio band selection, or keeping a network connection after Android force-stop. Actual file downloads still require a destination choice on Android. An always-connected state is best-effort, not an unconditional OS guarantee.
